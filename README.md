**Выжить в Тайге** — это многопользовательский интерактивный текстовый симулятор выживания в условиях дикой природы, построенный на базе **FastAPI (Python 3.14)** с использованием архитектурного паттерна **Clean Architecture (3-Tier)**.
 
Основной фокус разработки — строгое соблюдение принципов изоляции слоёв, иммутабельные DTO-контракты на `dataclasses` и полная независимость бизнес-логики от HTTP-протокола.

## 🎮 Игровой процесс
 
Игрок оказывается в условиях глухой тайги и сталкивается с серией сложных ситуаций на выживание — вопросы по ОБЖ, ботанике и ориентированию на местности. Каждый выбор напрямую влияет на три показателя жизнеобеспечения:
 
| Параметр | Описание |
| :---: | :--- |
| ❤️ **Здоровье** | Общее физическое состояние игрока |
| 🔥 **Тепло** | Уровень защиты от гипотермии |
| 🍗 **Сытость** | Показатель энергии и питания |
 
- **Победа:** ответить на все вопросы и дождаться спасателей.
- **Поражение:** любой из параметров падает до `0` — мгновенный конец игры.

## 🚀 Ключевые особенности
 
### 🏗 Архитектура
- **Clean Architecture / 3-Tier:** Строгое разделение на слой данных, бизнес-логики и веб-интерфейса. Изменения в одном слое не затрагивают остальные.
- **Иммутабельные DTO-контракты:** Слой данных возвращает `dataclass`-объекты — неизменяемые и типизированные. Бизнес-логика никогда не работает с сырыми словарями.
- **Modern Type Hints:** Используются `Generic`, `TypeAlias` и объединения типов через `|` в стиле Python 3.14.
### 🎯 Игровая механика
- **Динамические шкалы состояния:** `ScoreManager` пересчитывает все три параметра после каждого ответа на основе метаданных из `questions.json`.
- **Мгновенное поражение:** Проверка граничных значений происходит сразу после применения эффектов — игра не продолжается с нулевым параметром.
- **Асинхронный провайдер данных:** Вопросы загружаются асинхронно через `question_provider.py`, не блокируя основной поток сервера.
### 🧪 Тестирование
- Полное покрытие бизнес-логики через **Pytest** с конфигурацией в `pytest.ini` и фикстурами в `conftest.py`.
- Тестируются граничные случаи: падение шкал ниже нуля, поведение движка при исчерпании вопросов, корректность переходов состояний.
### 📋 Логирование
- Все ключевые события логируются в папку `logs/` и дублируются в консоль: старт сессии, выбор игрока, критическое состояние параметров, завершение игры.

## 📂 Структура проекта
 
```text
quiz_project/
│
├── core/                     # БИЗНЕС-ЛОГИКА (Core Layer)
│   ├── __init__.py
│   ├── quiz_engine.py        # Управление игровыми сессиями и валидацией ответов
│   └── score_manager.py      # Расчёт шкал состояния (Здоровье, Тепло, Сытость)
│
├── data/                     # СЛОЙ ДАННЫХ (Data Layer)
│   ├── __init__.py
│   ├── questions.json        # База вопросов и метаданные влияния на параметры
│   └── question_provider.py  # Асинхронный провайдер чтения данных
│
├── web/                      # СЛОЙ ИНТЕРФЕЙСА (Presentation Layer)
│   ├── __init__.py
│   ├── router.py             # API эндпоинты FastAPI
│   ├── static/
│   │   ├── css/
│   │   │   └── style.css     # Стили тайги, шрифты и Glassmorphism
│   │   └── js/
│   │       └── app.js        # Асинхронные fetch-запросы и обновление DOM
│   └── templates/
│       └── index.html        # Главная страница симулятора
│
├── tests/                    # МОДУЛЬНОЕ ТЕСТИРОВАНИЕ
│   └── test_quiz.py          # Тесты для quiz_engine и score_manager
│
├── utils/                    # ВСПОМОГАТЕЛЬНЫЕ СЛУЖБЫ
│   └── logger.py             # Конфигурация логирования игровых событий
│
├── logs/                     # Автоматически генерируемые лог-файлы
├── conftest.py               # Настройки фикстур pytest
├── pytest.ini                # Конфигурация запуска тестов
└── main.py                   # Точка входа приложения (запуск Uvicorn)
```

## 🛠 Инструкция по запуску
 
Для работы приложения необходим **Python 3.14+**.
 
```bash
# 1. Активировать виртуальное окружение (Windows)
.venv\Scripts\activate
 
# 2. Установить зависимости
pip install fastapi uvicorn pytest
 
# 3. Запустить сервер
python main.py
 
# 4. Открыть в браузере
# http://127.0.0.1:8000
```

## 🧪 Тестирование и логирование
 
### Запуск тестов
```bash
pytest
```
Конфигурация в `pytest.ini` автоматически подтянет фикстуры из `conftest.py`.
 
### Что тестируется
- Граничные случаи падения шкал ниже нуля
- Поведение движка при исчерпании вопросов
- Корректность переходов состояний викторины
### Логи
Все события сохраняются в `logs/` и выводятся в консоль:
 
| Событие | Описание |
| :--- | :--- |
| Старт сессии | Создание новой игровой сессии |
| Выбор игрока | Зафиксированный ответ и его эффект на параметры |
| Критическое состояние | Любой параметр опустился ниже порогового значения |
| Завершение игры | Победа или поражение с итоговыми параметрами |

## 📡 API Эндпоинты
 
| Метод | URL | Описание |
| :---: | :--- | :--- |
| `GET` | `/` | Главная страница симулятора |
| `POST` | `/api/session/start` | Создать новую игровую сессию |
| `GET` | `/api/question` | Получить текущий вопрос и состояние параметров |
| `POST` | `/api/answer` | Отправить ответ и получить обновлённые шкалы |
| `GET` | `/api/session/status` | Текущий статус сессии (активна / победа / поражение) |
